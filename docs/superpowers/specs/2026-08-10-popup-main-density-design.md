# VidBoost Popup 主页面紧凑布局设计

## 状态

已由用户确认，等待拆分实施计划。

## 背景与目标

VidBoost 的 Popup 固定为扩展弹窗尺寸，主页面包含通用、YouTube、Bilibili 三个功能分组和多个可展开设置项。当前版本的主要空间浪费来自顶栏、卡片之间的间距、分组标题高度以及固定底栏，而不是功能行的文字本身。

本设计的目标是在不显得拥挤的前提下，让 `360 x 600px` 的主页面首屏多显示约 2-3 个功能项，同时保持现有的功能语义、可读性、开关操作和分组状态记忆。

## 范围

包含：

- Popup 主页面的布局密度、间距、尺寸和信息层级。
- 主页面顶栏中的语言入口与总开关排布。
- GitHub 与版本信息在主页面滚动末尾的位置。
- 主页面 `SectionCard`、`ToggleItem`、`AccordionItem` 的密度样式。
- 主页面在中英文、浅色和深色模式下的视觉验收。

不包含：

- H5、自动暂停、Bilibili CDN 三个二级设置页的布局重做。
- 任何设置字段、功能逻辑、存储协议或权限调整。
- 新增功能、重排功能分组或改变默认展开状态。

## 已确认的用户决策

- 先只优化主页面，二级设置页后续单独处理。
- 采用平衡紧凑密度，而不是只做轻微压缩或高密度重构。
- 顶层分组保持独立展开，并继续记忆展开状态。
- 语言切换移动到顶栏，和总开关并列。
- 固定底栏取消；GitHub 与版本号作为滚动内容末尾的信息区显示。

## 设计

### 1. 页面骨架

Popup 仍保持 `360 x 600px`。顶栏固定约 `50px` 高，左侧显示 VidBoost，右侧依次显示语言按钮和总开关。主内容滚动区占据其余高度，不再为固定 Footer 预留空间。

主内容使用约 `12px` 的水平内边距，顶层卡片之间使用 `8px` 间距。分组标题控制在 `34-36px`，普通功能行控制在 `44-46px`。功能图标由 `32px` 缩至 `26-28px`，标题保留当前可读字号，说明保留单行并在空间不足时省略。

GitHub 与版本信息放在最后一个分组之后，作为普通滚动内容，高度约 `32px`。它们不使用 `position: fixed` 或 `position: sticky`；当内容超过可视区时，只有滚动到末尾才进入视野，内容不足一屏时则自然显示。GitHub 图标链接仓库，版本号链接 Releases。

### 2. 组件与交互

继续复用现有 `SectionCard`、`ToggleItem` 和 `AccordionItem`，只收紧主页面的密度样式。由于 `ToggleItem` 也被 H5 二级页使用，主页面密度必须通过显式的主页面样式作用域或密度参数实现，不能无条件压缩组件默认样式。

- `SectionCard`：压缩标题栏和卡片内边距，保留状态点、标题和展开箭头。
- `ToggleItem`：整行继续可切换；设置按钮保持独立点击；开关保留清晰的可点击区域。
- `AccordionItem`：左侧内容区负责展开，右侧主开关只负责启停，避免点击职责重叠。
- 展开内容：保留轻微色底区分，不增加额外嵌套卡片。
- 语言菜单：沿用现有菜单选项和关闭逻辑，入口移至顶栏，菜单向下并靠右展开，支持点击外部和 `Escape` 关闭。
- 总开关：保持现有启用/禁用语义，缩小视觉尺寸但不缩小可操作区域。

### 3. 状态与数据流

继续使用现有 `ui_state` 保存和恢复顶层分组展开状态。语言状态沿用现有逻辑。此次调整不新增设置字段，不改变设置加载、保存、禁用态或子项事件处理。

展开与收起动画统一缩短至约 `180-220ms`，以匹配更紧凑的内容节奏。设置读取失败时继续采用现有行为，不引入新的异步依赖或错误吞处理。

## 实施边界

预期变更集中在：

- `src/popup/App.svelte`：主页面骨架、顶栏语言入口、滚动末尾信息区和主页面密度作用域。
- `src/components/SectionCard.svelte`：支持主页面紧凑标题栏所需的显式样式入口。
- `src/components/ToggleItem.svelte`：增加或使用不影响二级页的主页面密度入口。
- `src/components/AccordionItem.svelte`：收紧主页面标题行和展开内容间距。
- `src/app.css`：抽取可复用的主页面密度 token 或作用域样式，避免散落重复值。

不应修改设置模型、功能模块、manifest 权限或二级设置页的现有视觉密度。

## 验收标准

- 在 `360 x 600px` Popup 中，主页面首屏较当前多显示约 2-3 个功能项。
- 中文和英文标题、说明、开关、设置按钮均无重叠或布局跳动。
- 通用、YouTube、Bilibili 可独立展开；刷新后展开状态保持。
- 语言按钮位于顶栏，菜单向下展开且不被 Popup 边界裁剪。
- GitHub 与版本号只位于滚动内容末尾，不固定占用底部高度。
- 总开关、分组开关、功能开关的启用和禁用行为与当前一致。
- 浅色和深色模式下层级、对比度和禁用态均可辨识。
- `npm run check` 通过，并完成主页面中英文、浅色/深色、分组展开/收起及滚动到底的手动检查。

## 非目标与取舍

本设计不移除功能说明、不改为单一分组互斥展开，也不通过明显缩小字体来换取空间。这样首屏增加的选项数量会低于高密度方案，但能保留首次使用时的理解成本和现有操作习惯。
